## Critical Issues

### [Security] Live credentials committed to version control

**File**: `.env:2`
**Severity**: CRITICAL

**Issue Description**:
The `.env` file contains a live Supabase database password (`qSQ8Q28zcNxHRRVw`) and a Context7 API key (`ctx7sk-39906062-...`). This file was committed and pushed to the remote repository, exposing secrets to anyone with repository access.

**Code Snippet**:
```env
DATABASE_URL=Host=db.qenyllwjorqeooooodsy.supabase.co;...Password=qSQ8Q28zcNxHRRVw;...
CONTEXT7_API_KEY=ctx7sk-39906062-4f62-478d-9653-3150b138996e
```

**Impact**:
Any person with repository read access — now or in the future — can access the production PostgreSQL database containing PHI. The exposed API key may also incur unauthorized charges. This constitutes a HIPAA breach risk if the database is accessed with these credentials.

**Fix Recommendation**:

1. **Immediately rotate all exposed credentials** — change the Supabase database password and regenerate the Context7 API key.
2. Remove the `.env` file from git history using `git filter-repo` or BFG Repo Cleaner.
3. Add `.env` to `.gitignore`.
4. Use environment variables or a secrets manager (e.g., GitHub Actions Secrets, Azure Key Vault) in all environments.

**Code Example**:
```bash
# Step 1: Add to .gitignore
echo ".env" >> .gitignore

# Step 2: Remove from git history (run after rotating credentials)
git filter-repo --path .env --invert-paths

# Step 3: Force-push the cleaned history (coordinate with team)
git push origin --force --all
```

### [Security] Production database password hardcoded in appsettings.json

**File**: `backend/src/UPACIP.API/appsettings.json:8`
**Severity**: CRITICAL

**Issue Description**:
`appsettings.json` contains the production Supabase database password in the `DefaultConnection` connection string. This file is committed to version control, permanently exposing the credential in git history.

**Code Snippet**:
```json
"DefaultConnection": "Host=aws-1-ap-south-1.pooler.supabase.com;...Password=qSQ8Q28zcNxHRRVw;..."
```

**Impact**:
Identical blast radius to CR-001 — full production database access for anyone with repository read. Additionally, `appsettings.json` is included in the build artifact, meaning it will ship inside Docker images or deployment packages if not explicitly excluded.

**Fix Recommendation**:

Replace the hardcoded connection string with an environment variable reference. ASP.NET Core's configuration system supports this natively via the `ConnectionStrings__DefaultConnection` environment variable, which overrides `appsettings.json` at runtime.

**Code Example**:
```json
// appsettings.json — placeholder only, never real credentials
{
  "ConnectionStrings": {
    "DefaultConnection": "SET_VIA_ENVIRONMENT_VARIABLE"
  }
}
```

```bash
# In production (GitHub Actions secret / Azure Key Vault / .env.local — gitignored)
export ConnectionStrings__DefaultConnection="Host=...;Password=<secret>;"
```

**References**:
- [ASP.NET Core — Safe storage of secrets (Microsoft Docs)](https://learn.microsoft.com/en-us/aspnet/core/security/app-secrets)

## High Severity Issues

### [Security] PHI captured fields stored as plaintext in sessionStorage

**File**: `frontend/src/hooks/useAIIntake.ts:55`
**Severity**: HIGH

**Issue Description**:
`saveToStorage()` serialises `capturedFields` — which contains PHI values such as chief complaint, allergies, and medications — into `sessionStorage` as unencrypted JSON. The UI labels responses as "encrypted and HIPAA-protected" but the local storage contains plaintext.

**Code Snippet**:
```ts
function saveToStorage(appointmentId: string, state: Partial<IntakeSessionState>): void {
  try {
    sessionStorage.setItem(storageKey(appointmentId), JSON.stringify(state));
  } catch { /* ... */ }
}
```

**Impact**:
Any JavaScript running on the same origin (e.g., a third-party analytics script, a browser extension, or an XSS payload) can read `sessionStorage` and extract all PHI fields. This contradicts the displayed "encrypted" messaging and risks HIPAA non-compliance.

**Fix Recommendation**:

Encrypt the JSON payload before writing to `sessionStorage` using the Web Crypto API. Derive a session-scoped key from a server-issued nonce so the stored data is unusable without the key.

**References**:
- [OWASP A02: Cryptographic Failures](https://owasp.org/Top10/A02_2021-Cryptographic_Failures/)
- [Web Crypto API — MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Crypto_API)

### [Security] AuthContext stub allows unauthenticated API calls

**File**: `frontend/src/context/AuthContext.tsx:18`
**Severity**: HIGH

**Issue Description**:
`AuthContext` defaults `token` to `null`. In `useAIIntake.ts`, `buildHeaders()` silently omits the `Authorization` header when `token` is null, causing all intake API calls to be sent without authentication. There is no redirect-to-login or guard when the user is unauthenticated.

**Code Snippet**:
```tsx
// AuthContext.tsx — stub defaults
export const AuthContext = createContext<AuthContextValue>({
  user: null,
  token: null,  // Always null — no auth provider wraps the app
});
```

```ts
// useAIIntake.ts — silently drops auth header
const buildHeaders = useCallback((): Record<string, string> => {
  const headers: Record<string, string> = { 'Content-Type': 'application/json' };
  if (token) headers['Authorization'] = `Bearer ${token}`;  // omitted when null
  return headers;
}, [token]);
```

**Impact**:
Unauthenticated users can reach the intake page and submit answers. The backend will return HTTP 401, but the UI shows a generic "Intake start failed: 401" error with no guidance to log in. This is a broken access control risk (OWASP A01, A07).

**Fix Recommendation**:

Add a guard in `IntakePage.tsx` that redirects unauthenticated users to the login page:

```tsx
// IntakePage.tsx
const { user, token } = useAuth();
const navigate = useNavigate();

useEffect(() => {
  if (!token) {
    navigate('/login', { replace: true, state: { from: location.pathname } });
  }
}, [token, navigate]);
```

Additionally, replace the `AuthContext` stub with a real implementation before shipping.

**References**:
- [OWASP A01: Broken Access Control](https://owasp.org/Top10/A01_2021-Broken_Access_Control/)
- [OWASP A07: Identification and Authentication Failures](https://owasp.org/Top10/A07_2021-Identification_and_Authentication_Failures/)

### [Logic] `useEffect` starts session with no abort cleanup on unmount

**File**: `frontend/src/pages/IntakePage.tsx:109`
**Severity**: MEDIUM

**Issue Description**:
`useEffect` calls `startSession()` on mount but returns no cleanup function. The `AbortController` created inside `startSession` is local to that async function and is never aborted when the component unmounts, causing state mutations on an unmounted component.

**Fix Recommendation**:

```tsx
// Option A: expose abortSession from the hook
useEffect(() => {
  if (mode === 'ai') {
    startSession();
    return () => abortSession(); // new hook export
  }
}, []); // eslint-disable-line react-hooks/exhaustive-deps
```

**Issue Description**:
`message.text` (sourced from Gemini API responses) is rendered directly via `<p>{message.text}</p>`. const MAX_AI_RESPONSE_LENGTH = 500;

### [Logic] `displayInitials` can produce undefined entries

**File**: `frontend/src/pages/IntakePage.tsx:156`
**Issue**: `user.displayName.split(' ').map((n) => n[0])` returns `undefined` for empty string segments (e.g. trailing spaces). The resulting `undefined` entries pass through `.join('')`, producing strings like `"Jundefined"`.

**Area**: Frontend routing (`App.tsx`)

// components/auth/ProtectedRoute.tsx

## Positive Findings

- **AES-256-GCM encryption**: `AesEncryptionService` uses GCM mode with a 96-bit random nonce and 128-bit tag per NIST SP 800-38D — correct and secure implementation.
- **Constant-time password verification**: `JwtAuthService.LoginAsync` uses a dummy hash path to prevent timing-oracle attacks on login — a sophisticated and often-missed security pattern.
- **Cookie-based JWT transport**: JWT is extracted from an HttpOnly `__Host-` prefixed cookie rather than `localStorage` or `Authorization` header — significantly reduces XSS token theft risk.
- **Session token rotation**: `RefreshAsync` issues a new session ID on every refresh, preventing session fixation attacks.
- **Startup credential validation**: `AesEncryptionService`, `GeminiClient`, and `JwtAuthService` all throw `InvalidOperationException` at startup when their secrets are missing — fail-fast pattern prevents silent runtime failures.
- **PHI field encryption via EF value converters**: `EncryptedStringConverter` transparently encrypts PHI columns at the ORM layer — correct architectural placement.
- **RBAC logging**: `RbacLoggingResultHandler` logs role claim at Warning level on HTTP 403 — provides audit trail for cross-role access attempts.
- **Quick-select chips (H-001)**: The `QuickOptions` component uses `role="group"` with an `aria-label` — proper ARIA grouping semantics.
- **AI audit logging**: `GeminiInvocationLogger` records prompt hash, token count, and latency for every Gemini call — good operational and compliance coverage.
- **Mobile responsive CSS**: `@media (max-width:480px)` correctly hides non-essential nav labels to prevent overflow at narrow viewports.
