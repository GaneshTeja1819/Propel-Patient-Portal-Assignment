# User Story - US_018

## Story ID
* ID Format: US_018

## Story Title
* AI Conversational Intake Powered by Gemini

## Description
* As an authenticated Patient with a booked appointment, I want to complete my pre-appointment intake through an AI-guided conversation, so that providing my health information feels natural and I can finish in less time than filling out a traditional form.

## Acceptance Criteria

### AC-001: AI intake conversation prompts with structured questions
- **Given**: An authenticated Patient selects the AI intake pathway for a booked appointment
- **When**: The intake session initialises
- **Then**: Gemini prompts the Patient with the first structured intake question in conversational language; each question maps to a defined intake field; the conversation is driven by the Gemini structured output function calling mode (FR-015, UC-009, AIR-001)

### AC-002: Patient responses are mapped to intake fields with schema validation
- **Given**: The Patient responds to a Gemini intake question
- **When**: Gemini processes the response
- **Then**: The response is mapped to the corresponding intake field in the structured IntakeRecord schema; the schema is validated before any field is populated; an unparseable response triggers a fallback manual input prompt for that field without stopping the conversation (UC-009 Extension 3a)

### AC-003: Intake summary is presented for patient review before persistence
- **Given**: All intake questions have been answered (or fallen back to manual)
- **When**: The conversation reaches the summary step
- **Then**: A summary of all captured fields is displayed to the Patient; the Patient can edit any field before confirming; no IntakeRecord is persisted until the Patient confirms (UC-009)

### AC-004: Confirmed intake is persisted with audit entry
- **Given**: The Patient reviews the intake summary and confirms
- **When**: The confirmation action is submitted
- **Then**: An IntakeRecord is created in the database linked to the appointmentId with method = "AI"; all PHI fields are encrypted before persistence; an audit log entry is written with actorId and timestamp (UC-009)

### AC-005: AI intake progress indicator is visible
- **Given**: The AI intake conversation is in progress
- **When**: Any question is being displayed
- **Then**: A progress bar or step counter is visible showing the current question number and total question count (e.g., "Question 3 of 8") and a completion percentage that advances with each answer (UXR-502)

## Edge Cases
* Gemini API rate limit exceeded mid-conversation → the current question is presented as a manual fallback input; the Patient can continue without interruption; the intake method is logged as "AI-Partial"
* Patient leaves the intake mid-conversation and returns later → partially captured fields are preserved in session state; the conversation resumes from the last unanswered question
* Gemini returns a schema-invalid response after maximum retries → the field is marked as requiring manual completion; the Patient is shown the manual input for that field; the conversation continues for remaining questions
