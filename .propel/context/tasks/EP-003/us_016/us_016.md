# User Story - US_016

## Story ID
* ID Format: US_016

## Story Title
* Register Preferred Slot During Booking

## Description
* As an authenticated Patient, I want to register a preferred (currently unavailable) slot during the booking flow, so that the system can automatically move me to my preferred time if it becomes available without me having to monitor availability manually.

## Acceptance Criteria

### AC-001: Preferred slot can be selected during the booking flow
- **Given**: An authenticated Patient has selected an available slot to book
- **When**: Unavailable slots are displayed in the booking screen with a "Register Preferred" option
- **Then**: The Patient can select exactly one unavailable slot as their preferred; the preferred slot selection is visually distinguished from available slot selection; the booking flow continues without interruption (UC-007)

### AC-002: WaitlistEntry is created linking patient, appointment, and preferred slot
- **Given**: The Patient has selected both an available slot (to book) and a preferred unavailable slot
- **When**: The booking is confirmed
- **Then**: A WaitlistEntry record is created containing the patientId, appointmentId, preferredSlotId, and registeredAt timestamp; the Patient sees an acknowledgement of their preferred slot registration (UC-007)

### AC-003: Skipping preferred slot selection proceeds without error
- **Given**: The Patient does not select a preferred slot during the booking flow
- **When**: The booking is confirmed
- **Then**: The booking completes normally with no WaitlistEntry created; no error or warning is shown to the Patient (UC-007 Extension 2a)

### AC-004: Duplicate preferred slot registration replaces existing entry
- **Given**: A WaitlistEntry already exists for the same patient and preferred slot
- **When**: The Patient registers the same preferred slot again
- **Then**: The existing WaitlistEntry is replaced (registeredAt is updated); only one WaitlistEntry exists for the patient-slot pair (UC-007 Extension 3a)

## Edge Cases
* Preferred slot becomes available between the Patient selecting it and confirming the booking → the booking proceeds normally; the Hangfire slot-swap job (US_017) evaluates the preferred slot and may trigger an immediate swap post-booking
* Patient books multiple appointments → each booking can have its own independent WaitlistEntry for a different preferred slot; no constraint prevents this
* Patient selects a preferred slot that is already in the same time block as their booked slot → the system validates that preferredSlotId ≠ booked slotId; if equal, the preferred selection is cleared and a validation message is shown
