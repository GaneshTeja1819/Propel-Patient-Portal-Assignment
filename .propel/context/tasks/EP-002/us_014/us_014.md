# User Story - US_014

## Story ID
* ID Format: US_014

## Story Title
* Cancel and Reschedule Appointment

## Description
* As an authenticated Patient, I want to cancel or reschedule an existing booked appointment, so that I can adjust my schedule while releasing my slot for other patients who need it.

## Acceptance Criteria

### AC-001: Cancellation marks appointment cancelled and releases slot
- **Given**: An authenticated Patient has a booked future appointment visible in their appointment list (SCR-003)
- **When**: The Patient selects the appointment, chooses "Cancel", and confirms the cancellation prompt
- **Then**: The Appointment status is set to "Cancelled"; the AppointmentSlot is released back to the available pool; any waitlisted patients for that slot are notified via a Hangfire job; an audit log entry is written (UC-005)

### AC-002: Cancellation prompt can be abandoned without effect
- **Given**: The cancellation confirmation prompt is displayed
- **When**: The Patient closes or dismisses the prompt without confirming
- **Then**: The Appointment remains in "Booked" status; the slot remains unavailable; no audit log entry is written for the abandoned cancellation (UC-005 Extension 4a)

### AC-003: Past appointments cannot be cancelled
- **Given**: An appointment whose date is in the past appears in the Patient's appointment list
- **When**: The Patient views the appointment detail
- **Then**: The "Cancel" action is disabled or hidden; no cancellation endpoint call can be made for past appointments (UC-005 Extension 2a)

### AC-004: Rescheduling atomically swaps slots
- **Given**: An authenticated Patient has a booked future appointment and at least one alternative slot is available
- **When**: The Patient selects "Reschedule", chooses a new available slot, and confirms
- **Then**: The old AppointmentSlot is released atomically; the new slot is reserved atomically in the same database transaction; the Appointment record is updated with the new slotId; an updated PDF confirmation is emailed; an audit log entry is written (UC-006)

### AC-005: Reschedule fails gracefully on concurrent slot conflict
- **Given**: The Patient selects a new slot that becomes unavailable between selection and confirmation
- **When**: The reschedule request is submitted
- **Then**: The API returns HTTP 409; neither slot state changes (rollback); the Patient sees a conflict error message and the slot grid refreshes (UC-006 Extension 3a)

## Edge Cases
* Patient cancels and immediately re-books the same slot → slot release and re-reservation happen in sequential requests; if another user claims the slot between the two requests, the re-booking returns HTTP 409
* Reschedule attempted when no alternative slots exist → the "Reschedule" flow displays an empty slot grid with an "No available slots" message; the existing appointment is unchanged
* Network failure during reschedule after old slot is released but before new slot is reserved → the transaction is rolled back atomically; neither slot state is permanently changed; the Patient sees a generic "Reschedule failed" error and must retry
