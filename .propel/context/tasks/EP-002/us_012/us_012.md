# User Story - US_012

## Story ID
* ID Format: US_012

## Story Title
* Real-Time Appointment Slot Availability Grid

## Description
* As an authenticated Patient, I want to view a real-time grid of available appointment slots that updates without a full page reload, so that I always see current availability and can select a slot that no one else has just taken.

## Acceptance Criteria

### AC-001: Slot grid renders available slots from Redis cache
- **Given**: An authenticated Patient navigates to the appointment booking screen
- **When**: The slot grid component mounts
- **Then**: Available slots are displayed within 500 ms; the data is served from the Redis cache (TTL ≤ 5 s); slot cards show date, time, and an "Available" status badge (FR-005, UXR-102)

### AC-002: Slot grid reflects state changes within 5 seconds without full reload
- **Given**: A slot is booked by another user while the Patient is viewing the grid
- **When**: Up to 5 seconds elapse (one cache TTL cycle)
- **Then**: The previously available slot transitions to an "Unavailable" state on the Patient's grid without a full page navigation; no manual refresh is required (FR-008, UXR-102)

### AC-003: Grid reflows to appropriate column count at each breakpoint
- **Given**: The slot grid is rendered at 375 px, 768 px, and 1280 px viewports
- **When**: The viewport is set to each breakpoint width
- **Then**: At 1280 px the grid renders in 4 columns; at 768 px in 2 columns; at 375 px in 1 column; no horizontal scroll appears at any breakpoint (UXR-302)

### AC-004: Optimistic slot selection provides 200 ms visual feedback
- **Given**: An available slot card is rendered in the grid
- **When**: The Patient clicks a slot card
- **Then**: The card transitions to a "Selected" visual state (highlighted border, colour token applied) within 200 ms of the click event, before any server response is received (UXR-501)

### AC-005: Empty state is displayed when no slots are available
- **Given**: All appointment slots for the current date are booked
- **When**: The Patient views the slot grid
- **Then**: An empty-state message is displayed ("No available slots — try another date"); no slot cards are rendered; no error is thrown

## Edge Cases
* Redis cache is unavailable → slot data falls through to a direct PostgreSQL query; a "Showing live data" badge replaces the cached indicator; response time may exceed 100 ms but the grid still renders
* Patient has a very slow connection and the slot grid takes > 2 s to load → a loading skeleton (placeholder cards) is displayed immediately on mount; the grid replaces the skeleton when data arrives
* Two patients select the same slot simultaneously → the grid shows both as "Selected" briefly; the booking AC-001 in US_013 resolves the conflict via optimistic concurrency; the losing patient sees the slot revert to "Unavailable" with an error toast
