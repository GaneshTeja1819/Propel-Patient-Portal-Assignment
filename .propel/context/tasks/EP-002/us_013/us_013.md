# User Story - US_013

## Story ID
* ID Format: US_013

## Story Title
* Book Appointment with Insurance Pre-Check and No-Show Risk Score

## Description
* As an authenticated Patient, I want to book an available appointment slot with an inline insurance soft-validation and no-show risk assessment, so that my appointment is confirmed without being blocked by insurance issues and the clinic is informed of my no-show risk at booking time.

## Acceptance Criteria

### AC-001: Appointment is created and slot is marked booked
- **Given**: An authenticated Patient has selected an available slot on the booking screen
- **When**: The Patient completes the booking form and confirms
- **Then**: An Appointment record is created with status "Booked"; the selected AppointmentSlot is marked as booked; the slot is removed from the available grid immediately; the booking is confirmed on-screen (UC-004)

### AC-002: No-show risk score is calculated and stored
- **Given**: An Appointment record is being created
- **When**: The booking form is submitted
- **Then**: A rule-based no-show risk score is computed (based on configurable factors such as previous no-shows, lead time); the score is stored on the Appointment record; no UI error occurs if the scoring logic returns a default value (FR-014)

### AC-003: Insurance soft-validation shows inline result without blocking
- **Given**: The Patient enters an insurance provider name and insurance ID in the booking form
- **When**: The values are validated against the dummy InsuranceRecord dataset
- **Then**: A "Validated" green badge or "Not Recognised" amber advisory is displayed inline beside the insurance fields; the booking CTA remains enabled in both states; the validation result is stored on the Appointment record (FR-029, UC-018, UXR-602)

### AC-004: Slot conflict returns error and refreshes grid
- **Given**: The Patient has selected a slot that becomes unavailable between selection and submission
- **When**: The booking request reaches the server with an optimistic concurrency conflict
- **Then**: The API returns HTTP 409; an error toast "Slot no longer available" appears within 2 s of the response; the slot grid refreshes and the previously selected slot is shown as unavailable (UC-004 Extension 3a, UXR-601)

### AC-005: Booking completes within 3 primary interactions from dashboard
- **Given**: An authenticated Patient starts from the Patient dashboard (SCR-003)
- **When**: The Patient completes the booking flow (slot selection → form completion → confirm)
- **Then**: The booking confirmation is reached in ≤ 3 screen transitions; no intermediate confirmation pages are required (UXR-101)

## Edge Cases
* Insurance fields are left blank → soft validation is skipped; the Appointment record stores a null insuranceValidationResult; booking is not blocked
* No-show risk scoring service throws an exception → the booking proceeds with a default risk score of 0; the exception is logged; no user-facing error is shown
* Patient attempts to book a second appointment while one is already booked for the same time → server returns HTTP 409 with a "You already have an appointment at this time" message; no duplicate is created
