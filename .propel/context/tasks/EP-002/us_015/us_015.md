# User Story - US_015

## Story ID
* ID Format: US_015

## Story Title
* Generate and Email PDF Appointment Confirmation

## Description
* As an authenticated Patient, I want a PDF appointment confirmation generated and emailed to me immediately after every successful booking or rescheduling, so that I have a permanent record of my appointment details without needing to log back in.

## Acceptance Criteria

### AC-001: PDF confirmation is generated and emailed after successful booking
- **Given**: An Appointment record has just been created successfully
- **When**: The Hangfire PDF generation job is triggered immediately after booking confirmation
- **Then**: A PDF is rendered using QuestPDF containing appointment ID, patient name, date, time, and provider; the PDF is sent as an email attachment to the patient's registered email address; the delivery status is logged (FR-009, UC-025)

### AC-002: In-progress PDF generation is indicated on the booking screen
- **Given**: The booking confirmation screen is displayed after a successful booking
- **When**: The Hangfire PDF job is in progress
- **Then**: A "Generating confirmation..." spinner is visible on the booking confirmation screen; it is replaced by a "Confirmation emailed ✓" message within the Hangfire job completion window (UXR-504)

### AC-003: PDF generation failure is retried and does not block the appointment
- **Given**: The QuestPDF rendering step throws an exception
- **When**: Hangfire processes the job
- **Then**: The job is retried once; if the second attempt also fails, the job transitions to "Failed" state; the Appointment record remains in "Booked" status; an audit log entry records the generation failure; the patient is not shown an error blocking their booking (UC-025 Extension 3a)

### AC-004: Email delivery failure is logged with retry
- **Given**: The SMTP gateway is unavailable when the PDF dispatch is attempted
- **When**: The email dispatch step runs
- **Then**: The dispatch is retried up to the configured maximum (3 attempts with exponential back-off); after all retries fail, the delivery status is marked "Failed" in the Notification record; the Appointment is unaffected (UC-025 Extension 4a)

### AC-005: Rescheduled appointment triggers an updated confirmation
- **Given**: A Patient successfully reschedules an appointment to a new slot
- **When**: The reschedule completes
- **Then**: A new PDF confirmation is generated with the updated appointment date and time; it is emailed to the patient; the subject line includes "Updated Appointment Confirmation"

## Edge Cases
* Patient's email address is malformed or no longer valid → SMTP gateway returns a bounce; the delivery failure is logged in the Notification record; the Appointment is unaffected; no retry occurs for permanent bounce codes (5xx SMTP)
* Hangfire job is picked up by multiple workers simultaneously → idempotency key on the Hangfire job prevents duplicate PDF generation; only one email is delivered per booking event
* PDF template variable (e.g., patient name) contains special characters → QuestPDF renders the value escaped; no template injection or rendering exception occurs
