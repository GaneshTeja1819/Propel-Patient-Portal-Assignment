# User Story - US_030

## Story ID
* ID Format: US_030

## Story Title
* Staff Medical Code Verification with Immutable Audit Trail

## Description
* As an authenticated Staff member, I want to review each AI-suggested ICD-10 and CPT code and individually Accept, Modify, or Reject it before finalising the clinical coding for an encounter, so that all codes submitted to billing are clinician-verified and every decision is permanently recorded.

## Acceptance Criteria

### AC-001: Code verification screen renders all suggestions for review
- **Given**: MedicalCodeSuggestion records exist for a patient encounter
- **When**: An authenticated Staff member navigates to the code verification screen (SCR-014)
- **Then**: All ICD-10 and CPT suggestions are displayed in rank order; each row shows suggestedCode, description, confidenceScore badge, and Accept / Modify / Reject action controls; suggestions with confidenceScore < 0.5 are visually distinguished with an amber "Low confidence" indicator (FR-039, UC-024, UXR-107)

### AC-002: Staff accepts a code — immutable audit entry created
- **Given**: A suggestion is displayed and the Staff selects "Accept"
- **When**: The acceptance is confirmed
- **Then**: A VerifiedMedicalCode record is created with verifiedCode = suggestedCode and decision = "Accepted"; an immutable AuditLog entry is written with actionType = "CODE_VERIFIED", actorId (Staff), codeType, verifiedCode, and timestamp; the row is marked with a "Accepted" badge and cannot be changed after submission (AIR-005)

### AC-003: Staff modifies a code — modified value validated against codeset
- **Given**: A suggestion is displayed and the Staff selects "Modify" and enters a custom code
- **When**: The modified code is submitted
- **Then**: The entered code is validated against the reference ICD-10 or CPT codeset; if valid, a VerifiedMedicalCode record is created with verifiedCode = modified code and decision = "Modified"; an immutable audit entry records both the original suggestion and the final verified code; if the entered code is not in the codeset, an inline validation error is shown and no record is created (UC-024 Extension 3a)

### AC-004: Staff rejects a code — individual rejection audited
- **Given**: A suggestion is displayed and the Staff selects "Reject"
- **When**: The rejection is confirmed
- **Then**: The suggestion is marked as "Rejected"; a VerifiedMedicalCode record is created with decision = "Rejected"; an immutable audit entry records the rejection with the Staff actor's ID and timestamp

### AC-005: All-rejection state flags encounter for manual coding
- **Given**: All MedicalCodeSuggestion records for an encounter are rejected
- **When**: The last rejection is submitted
- **Then**: The encounter is flagged with status "PendingManualCoding"; a banner on SCR-014 reads "All suggestions rejected — manual coding required"; an audit entry records the mass rejection event; no billing submission is made for this encounter until at least one code is verified (UC-024 Extension 3b)

## Edge Cases
* Staff submits all verifications then navigates away → all VerifiedMedicalCode records are created on individual Accept/Modify/Reject actions (not on a final "Submit" button); navigating away after all rows are actioned does not create a partial state
* Staff attempts to modify a code after the encounter has been submitted to billing → the modification action is blocked with "This encounter has been finalised"; the VerifiedMedicalCode record and audit entry cannot be changed
* SCR-014 is opened by a Patient-role user → the API returns HTTP 403; the frontend routes the Patient to their dashboard; no code data is returned to the Patient session
