# User Story - US_029

## Story ID
* ID Format: US_029

## Story Title
* AI ICD-10 and CPT Code Suggestion Generation

## Description
* As a Staff member awaiting code suggestions for a patient encounter, I want the system to automatically generate ranked ICD-10 diagnosis and CPT procedure code candidates from the patient's extracted clinical data, so that I can quickly review and verify codes rather than looking them up manually.

## Acceptance Criteria

### AC-001: Code suggestion generation is triggered after extraction or on demand
- **Given**: A patient's ExtractedClinicalData record exists
- **When**: Extraction completes (triggered automatically) or a Staff member manually requests code suggestion from the verification screen
- **Then**: A Hangfire code suggestion job is queued; the job invokes the Gemini API with the extracted clinical data and a structured ICD-10/CPT suggestion prompt; ranked candidates are stored in MedicalCodeSuggestion records (FR-037, UC-023, AIR-003)

### AC-002: Gemini returns ranked candidates with confidence scores
- **Given**: The code suggestion Gemini prompt is submitted with extracted clinical data
- **When**: Gemini returns a valid structured response
- **Then**: Each MedicalCodeSuggestion record contains: codeType (ICD10 / CPT), suggestedCode (validated against reference codeset), rank, confidenceScore (0.00–1.00), and derivedFrom (pointer to ExtractedClinicalData); at least one ICD-10 and one CPT candidate are stored when the clinical data supports them

### AC-003: Zero suggestions state is stored and surfaced to Staff
- **Given**: Gemini cannot derive any code candidates from the clinical data
- **When**: The suggestion job completes
- **Then**: The MedicalCodeSuggestion table has no records for this encounter; the code verification screen (SCR-014) displays a "No codes suggested — manual coding required" state; the suggestion failure is written to the audit log (UC-023 Extension 2a)

### AC-004: Every Gemini invocation is logged as an AI_INVOCATION audit entry
- **Given**: A Gemini API call is made for code suggestion
- **When**: The call completes (success or failure)
- **Then**: An audit log entry with actionType = "AI_INVOCATION" is written containing modelVersion, promptHash, inputTokenCount, outputTokenCount, responseLatencyMs, httpStatusCode, and timestamp (AIR-003, AIR-006)

### AC-005: Gemini failure retries once and notifies Staff to code manually
- **Given**: The Gemini API call for code suggestion fails or returns an invalid schema
- **When**: The Hangfire job processes the failure
- **Then**: The job retries exactly once; if the retry also fails, a "Code suggestion failed — please code manually" notification is shown on the code verification screen; the ExtractedClinicalData record is unchanged (UC-023 Extension 3a)

## Edge Cases
* Extracted clinical data contains unrecognised or non-standard clinical terminology → Gemini returns low-confidence suggestions; the low-confidence codes are still returned and stored; the Staff can still accept, modify, or reject them in UC-024
* Code suggestion job runs before de-duplication completes → the job uses the available (potentially duplicated) extracted data; once de-duplication completes, Staff can request a code regeneration via the "Regenerate" CTA on SCR-014
* Concurrent code suggestion jobs are queued for the same patient encounter → the second job detects an existing "Pending/Processing" MedicalCodeSuggestion set for the same ExtractedClinicalData and exits without re-invoking Gemini (idempotency guard)
