# User Story - US_025

## Story ID
* ID Format: US_025

## Story Title
* Patient Clinical Document Upload with Encrypted Storage

## Description
* As an authenticated Patient, I want to upload my historical clinical documents and post-visit clinical notes as PDF files, so that my medical history is available to the clinic's clinical intelligence engine without me having to bring physical copies.

## Acceptance Criteria

### AC-001: Patient can upload a valid PDF and receive confirmation
- **Given**: An authenticated Patient navigates to the document upload screen (SCR-010)
- **When**: The Patient selects a valid PDF file and a document type (Historical / Post-visit) and confirms the upload
- **Then**: The file is stored in Supabase Storage with server-side encryption; a ClinicalDocument record is created with storagePath (encrypted), documentType, uploadedAt, and extractionStatus = "Pending"; an audit log entry is written; a "Document uploaded successfully" confirmation is shown (FR-030, FR-031, UC-019)

### AC-002: Invalid file type is rejected with a format error
- **Given**: The Patient selects a non-PDF file (e.g., .docx or .jpg)
- **When**: The upload is submitted
- **Then**: The file is rejected before any upload attempt; a "Only PDF files are accepted" error message is displayed inline; no ClinicalDocument record is created (UC-019 Extension 3a)

### AC-003: Oversized file is rejected with a size error
- **Given**: The Patient selects a PDF file exceeding the maximum size limit (e.g., > 10 MB)
- **When**: The upload is submitted
- **Then**: The upload is rejected client-side before the request is sent; a "File exceeds maximum size of [limit]" error message is displayed; no upload request is made to the server (UC-019 Extension 3b)

### AC-004: AI extraction job is queued after successful upload
- **Given**: A ClinicalDocument record has been created with extractionStatus = "Pending"
- **When**: The upload completes
- **Then**: A Hangfire AI extraction job is queued for the document within 5 seconds; the document's extractionStatus transitions to "Processing" when the job starts (UC-019)

### AC-005: Document content (binary) is not stored in the relational database
- **Given**: A PDF has been uploaded and the ClinicalDocument row is read from PostgreSQL
- **When**: The storagePath column is inspected
- **Then**: The column contains an encrypted path string pointing to Supabase Storage; no binary PDF content is present in any relational database column (DR-005)

## Edge Cases
* Patient uploads the same PDF twice → a duplicate check based on file hash (SHA-256) detects the duplicate; the Patient is warned "This document appears to have been uploaded already"; they can proceed or cancel
* Supabase Storage free-tier limit is reached → the upload returns a storage error; the Patient is shown "Storage limit reached — contact support"; no partial ClinicalDocument record is created
* PDF is password-protected → PdfPig extraction in US_026 will fail; the ClinicalDocument is stored successfully but extractionStatus is set to "Failed" after the extraction attempt; the Patient is notified via UXR-603 (handled in US_026)
