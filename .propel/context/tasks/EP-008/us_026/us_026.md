# User Story - US_026

## Story ID
* ID Format: US_026

## Story Title
* AI Clinical Data Extraction Pipeline

## Description
* As a Staff member reviewing patient records, I want the system to automatically extract structured clinical data (vitals, medications, diagnoses) from uploaded PDFs using Gemini AI, so that the patient's 360° profile is populated without manual data entry and the extraction is fully auditable.

## Acceptance Criteria

### AC-001: Hangfire job extracts text and invokes Gemini with schema validation
- **Given**: A ClinicalDocument exists with extractionStatus = "Processing" and a valid non-password-protected PDF in storage
- **When**: The Hangfire extraction job executes
- **Then**: PdfPig extracts the PDF text; the text is sent to Gemini with a structured extraction prompt; Gemini returns JSON matching the ExtractedClinicalData schema; the schema is validated before any field is persisted; extractionStatus transitions to "Completed" (FR-032, FR-033, UC-021, AIR-002)

### AC-002: Extracted data is stored with PHI encrypted
- **Given**: Gemini returns a valid extraction response
- **When**: The ExtractedClinicalData record is created
- **Then**: All PHI fields (vitals, medications, diagnoses, rawGeminiResponse) are encrypted with AES-256-GCM before persistence; the modelVersion and promptHash (SHA-256) are stored unencrypted for auditability

### AC-003: Every Gemini invocation is logged as an AI_INVOCATION audit entry
- **Given**: A Gemini API call is made for clinical extraction
- **When**: The call completes (success or failure)
- **Then**: An audit log entry with actionType = "AI_INVOCATION" is written containing: modelVersion, promptHash, inputTokenCount, outputTokenCount, responseLatencyMs, httpStatusCode, and timestamp (AIR-006)

### AC-004: Gemini failure retries twice then sets Failed status with Staff CTA
- **Given**: The Gemini API call fails or returns a schema-invalid response
- **When**: The Hangfire job processes the failure
- **Then**: The job retries up to 2 times with exponential back-off; after all retries fail, extractionStatus is set to "Failed"; on the document upload or profile screen a "Extraction failed — contact staff or retry" message with a retry button is displayed (AIR-007, UC-021 Extension 3a, UXR-603)

### AC-005: De-duplication and conflict pipeline is triggered after extraction
- **Given**: An ExtractedClinicalData record has been successfully persisted
- **When**: The extraction job completes
- **Then**: A downstream Hangfire job for de-duplication and conflict detection (feeding EP-009/US_027) is queued; the extraction job does not wait for the downstream job to complete

## Edge Cases
* PDF contains only scanned images with no extractable text → PdfPig returns an empty string; the Gemini prompt receives an empty input; Gemini returns an empty extraction; extractionStatus is set to "Failed" with a "No text extracted from document" note
* Gemini rate limit is hit during extraction → the job retries with back-off; if rate limit persists across all retries, extractionStatus is "Failed"; the Hangfire dashboard shows the failure reason as "Rate limit exceeded"
* ExtractedClinicalData schema evolves between the time of upload and extraction → a schema version field on the extraction job ensures the correct schema version is used; mismatched schemas fail validation and are logged without silent data loss
