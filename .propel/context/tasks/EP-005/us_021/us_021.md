# User Story - US_021

## Story ID
* ID Format: US_021

## Story Title
* Google and Outlook Calendar Sync via OAuth 2.0

## Description
* As an authenticated Patient, I want my booked appointments to automatically appear in my Google or Outlook calendar, so that I can see all my commitments in one place without manually creating calendar entries.

## Acceptance Criteria

### AC-001: Patient grants OAuth consent and calendar event is created
- **Given**: An authenticated Patient navigates to the calendar sync OAuth prompt (SCR-016) during or after booking
- **When**: The Patient grants OAuth consent for Google Calendar or Outlook Calendar
- **Then**: A calendar event is created in the authorised provider with appointment date, time, and a description containing the appointment ID; the CalendarSync record is created with provider, encrypted tokens, and syncStatus = "Synced" (FR-020, FR-021, UC-013, TR-009)

### AC-002: Calendar event is updated when appointment is rescheduled
- **Given**: A CalendarSync record exists for a patient's appointment and the appointment is rescheduled
- **When**: The reschedule completes
- **Then**: The existing calendar event is updated via the provider API to reflect the new date and time; the CalendarSync record's lastSyncAt is updated

### AC-003: Calendar event is deleted when appointment is cancelled
- **Given**: A CalendarSync record exists for a patient's appointment and the appointment is cancelled
- **When**: The cancellation completes
- **Then**: The calendar event is deleted via the provider API; the CalendarSync record syncStatus is set to "Deleted"

### AC-004: Calendar sync failure shows non-blocking amber Toast
- **Given**: A calendar API call fails after all retries
- **When**: The failure is detected
- **Then**: A dismissible amber Toast notification ("Calendar sync failed — your appointment is still confirmed") appears on the booking confirmation screen; the appointment confirmation is fully visible and unobstructed; no modal or blocking error is shown (UXR-604)

### AC-005: Denied OAuth consent proceeds without calendar sync
- **Given**: The Patient dismisses or denies the OAuth consent flow
- **When**: The denial is processed
- **Then**: The booking proceeds normally; no CalendarSync record is created; no error is shown; the Patient is informed that calendar sync is optional (UC-013 Extension 1a)

## Edge Cases
* OAuth access token expires between appointment creation and sync → the Infrastructure layer's token refresh handler attempts to refresh before the API call; if refresh also fails, the sync is logged as failed and the patient may re-authorise
* Patient grants consent for both Google and Outlook → two CalendarSync records are created; events are created in both providers independently; failure in one does not block the other
* Calendar API rate limit hit → the sync is retried with exponential back-off; if all retries fail, the CalendarSync record status is set to "Failed" and the amber Toast is shown
