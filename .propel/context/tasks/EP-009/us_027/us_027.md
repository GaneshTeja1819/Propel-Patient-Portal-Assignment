# User Story - US_027

## Story ID
* ID Format: US_027

## Story Title
* 360° Patient Profile with AI De-duplication

## Description
* As a Staff member, I want to view a unified patient profile that consolidates all extracted clinical data across every uploaded document into a single chronological summary, so that I can understand a patient's complete clinical picture without switching between documents.

## Acceptance Criteria

### AC-001: Staff views unified patient profile with all clinical sections
- **Given**: An authenticated Staff member navigates to a patient's profile on the staff patient profile screen (SCR-013)
- **When**: The page loads
- **Then**: Vitals, medications, diagnoses, and visit history sections are displayed; data is sourced from all ExtractedClinicalData records for the patient; sections with no data show an "No data available" empty state (FR-034, UC-020, UXR-402)

### AC-002: Patient views their own read-only profile
- **Given**: An authenticated Patient navigates to their profile (SCR-009)
- **When**: The page loads
- **Then**: The same clinical sections are rendered in read-only mode with a "Patient view" indicator; no Staff-only conflict review controls are visible; the AI-extracted fields are clearly labelled as "AI-extracted" (FR-034, UC-020, UXR-106, UXR-403)

### AC-003: AI de-duplication merges overlapping entries from multiple documents
- **Given**: A patient has uploaded two documents containing the same medication (e.g., "Metformin 500 mg" and "metformin 500mg")
- **When**: The de-duplication pipeline runs (triggered by US_026)
- **Then**: Only one canonical medication entry appears in the medications section; the merged entry links to both source documents; no duplicate entry is visible in the profile (FR-036, AIR-004)

### AC-004: No-document state shows upload guidance CTA
- **Given**: A patient has no processed ClinicalDocument records
- **When**: Staff or Patient views the profile
- **Then**: The profile renders a "No clinical data available" message with a CTA linking to the document upload screen (SCR-010) in place of the clinical sections (UC-020 Extension 2a)

### AC-005: Profile loads within the API P95 threshold
- **Given**: A patient with up to 10 processed documents
- **When**: The profile is requested
- **Then**: The API responds within 500 ms at P95; all UI sections are fully rendered within 2 s on a standard connection (NFR-004)

## Edge Cases
* De-duplication pipeline has not yet completed when Staff views the profile → the profile renders with raw, potentially duplicated entries; a "Profile consolidation in progress" banner is shown; no error is thrown
* Patient has a very large clinical history (> 50 entries per section) → pagination or virtual scrolling is applied per section at 20 entries per page; no more than 20 rows are rendered to the DOM simultaneously
* Staff and Patient access the same profile concurrently → each renders their respective view (read-write for Staff, read-only for Patient); no locking or conflict at the read layer
