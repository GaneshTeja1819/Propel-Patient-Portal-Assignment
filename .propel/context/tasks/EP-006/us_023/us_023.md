# User Story - US_023

## Story ID
* ID Format: US_023

## Story Title
* Same-Day Queue Management and Patient Arrival

## Description
* As an authenticated Staff member, I want to view and manage the same-day patient queue and mark patients as arrived when they check in at the front desk, so that the clinic day flows smoothly and all patient movements are tracked with a Staff-attributed audit trail.

## Acceptance Criteria

### AC-001: Same-day queue dashboard shows all today's appointments
- **Given**: An authenticated Staff member navigates to the same-day queue dashboard (SCR-011)
- **When**: The page loads
- **Then**: All appointments for the current day are displayed in chronological order; each entry shows patient name, scheduled time, and status badge (Booked / Arrived / Cancelled); all entries are visible without scroll on a 1280 px viewport (FR-024, UC-015, UXR-104)

### AC-002: Staff can reorder queue entries
- **Given**: Two entries are visible in the same-day queue
- **When**: The Staff drags an entry to a new position in the queue
- **Then**: The reordered position is saved; if the reorder conflicts with a slot constraint, a warning is displayed but the override is allowed; each reorder is written to the audit log (UC-015)

### AC-003: Staff can remove a patient from the queue with reason
- **Given**: A patient entry exists in the same-day queue
- **When**: The Staff selects "Remove" and enters a mandatory reason (e.g., "No-show", "Error")
- **Then**: The queue entry is removed; the Appointment status is updated; the reason is stored in the audit log entry; a confirmation message is shown to the Staff (UC-015 Extension 4a)

### AC-004: Staff marks a patient as arrived
- **Given**: A patient with a booked appointment is in the same-day queue
- **When**: The Staff selects "Mark Arrived" for the patient's queue entry
- **Then**: The Appointment status is updated to "Arrived"; an arrival timestamp and the Staff actor's ID are recorded in the audit log; the status badge in the queue updates to "Arrived" (FR-025, UC-016)

### AC-005: Patient self-check-in is blocked at the API
- **Given**: An authenticated Patient attempts to call the arrival endpoint directly
- **When**: The request reaches the API
- **Then**: The API returns HTTP 403 for any Patient-role request to any arrival endpoint; no appointment status changes; the PatientPolicy denies the request (FR-026, UC-016 Extension 1a)

## Edge Cases
* Staff removes a patient who has already been marked Arrived → the system displays a confirmation warning "Patient has already arrived — confirm removal?"; the removal proceeds only if the Staff confirms; the audit log records the override with the Staff actor
* Two Staff members attempt to mark the same patient as arrived simultaneously → the second request detects the appointment is already "Arrived" and returns HTTP 409 with a message "Patient already marked as arrived"; no duplicate audit entry is created
* Queue rendered on a tablet (768 px) → all columns remain visible with responsive layout; no horizontal scroll; status badges remain legible
