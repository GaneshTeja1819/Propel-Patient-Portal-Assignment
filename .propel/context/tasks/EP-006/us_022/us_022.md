# User Story - US_022

## Story ID
* ID Format: US_022

## Story Title
* Staff Walk-in Booking with Patient Account Creation

## Description
* As an authenticated Staff member, I want to book an appointment for a walk-in patient and optionally create a patient account for them, so that same-day patients are served efficiently without requiring them to log in or self-register.

## Acceptance Criteria

### AC-001: Staff books a walk-in appointment for an existing patient
- **Given**: An authenticated Staff member navigates to the walk-in booking screen (SCR-012)
- **When**: The Staff searches for and selects an existing patient account, selects an available slot, and confirms
- **Then**: An Appointment record is created with status "Booked" and createdByStaffId set to the Staff actor's ID; the slot is marked as booked; an audit log entry is written attributing the booking to the Staff actor (FR-022, UC-014)

### AC-002: Staff books for an anonymous walk-in without an existing account
- **Given**: No matching patient account is found in the search
- **When**: The Staff enters the patient's details and books without creating an account
- **Then**: The Appointment is created with anonymous patient details; no User record is required; the audit log entry records the Staff actor and the anonymous booking nature (UC-014 Extension 2a)

### AC-003: Staff optionally creates a patient account and links it to the walk-in
- **Given**: A walk-in appointment has been created for an anonymous patient
- **When**: The Staff selects "Create patient account" and enters email and profile details
- **Then**: A new Patient User record is created; the Appointment record is updated to link the new patientId; the audit log records both the account creation and the link action; the Staff actor is attributed for both actions (FR-023, UC-014)

### AC-004: Walk-in booking is attributed to Staff actor, not Patient
- **Given**: A Staff member books a walk-in appointment
- **When**: The audit log is reviewed for the booking event
- **Then**: The audit log entry shows actorRole = "Staff" and actorId = the Staff user's ID; no Patient actor attribution appears on the booking event

### AC-005: No available slots redirects to queue option
- **Given**: No appointment slots are available for the current day
- **When**: The Staff attempts a walk-in booking
- **Then**: The booking screen displays "No available slots" with a CTA to add the patient directly to the same-day queue (UC-014 Extension 3a)

## Edge Cases
* Duplicate patient account creation attempt (email already exists) → the Staff is informed the email is already registered; they are offered the option to link the walk-in to the existing account instead
* Staff creates a patient account with a weak password → the same password complexity rules as self-registration apply; a validation error is shown inline
* Network failure after slot is reserved but before Appointment is created → the transaction is rolled back atomically; the slot is released; the Staff sees a "Booking failed" error and can retry
