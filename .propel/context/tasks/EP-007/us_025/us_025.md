# User Story - US_025

## Story ID
* ID Format: US_025

## Story Title
* Admin Audit Log Viewer

## Description
* As an authenticated Admin, I want to view, filter, and export the platform's immutable audit log, so that I can monitor all system activity, investigate security incidents, verify compliance with HIPAA audit-control requirements, and demonstrate accountability for every action taken on the platform.

## Acceptance Criteria

### AC-001: Admin can view a paginated audit log showing all platform events
- **Given**: An authenticated Admin navigates to the Audit Log screen (SCR-017)
- **When**: The page loads
- **Then**: A paginated table (15 rows per page) is displayed showing all audit events sorted newest-first; each row shows timestamp (ISO 8601), actor name, actor role, action type, resource/target, source IP address, and success/failure status; summary stat strip shows events today, unique users, PHI access events, and failed attempts (FR-042, UC-026)

### AC-002: Admin can filter audit events by date range, action category, role, status, and free-text search
- **Given**: An authenticated Admin is on SCR-017
- **When**: The Admin applies one or more filter controls (from/to date, action category, role, status, search text)
- **Then**: The table updates to show only matching events; the event count label reflects the filtered total; "✕ Reset" clears all filters and restores the full result set (FR-042)

### AC-003: Admin can expand any event row to see full detail
- **Given**: An authenticated Admin is viewing an audit event row
- **When**: The Admin clicks "Detail ▾" on a row
- **Then**: An inline expand panel opens showing event ID, correlation ID, session ID, ISO 8601 timestamp, actor ID/name/role/IP, resource, payload JSON (non-PHI fields), and an immutable-record notice; only one row can be expanded at a time; Escape key closes the panel (FR-042)

### AC-004: PHI-access events are visually distinguished with a 🔒 PHI indicator
- **Given**: An audit event involves access to Protected Health Information (patient profile view, document upload, intake submission, code verification)
- **When**: That event is displayed in the table or the expand panel
- **Then**: A 🔒 PHI inline indicator is shown in the action column; the detail panel labels the patient ID field as "🔒 [id] (PHI)"; the HIPAA access notice banner is displayed at the top of the page (FR-042, NFR-004, BRD §7.1)

### AC-005: Admin can export the visible filtered audit log as a CSV file
- **Given**: An authenticated Admin has optionally applied filters
- **When**: The Admin clicks "Export CSV"
- **Then**: A CSV file is generated containing all events matching the current filter (or all events if no filter is active); a toast notification confirms the export; the export action itself is written as an `AUDIT_LOG_EXPORTED` entry to the audit log; the export endpoint is Admin-only (FR-042, UC-026)

### AC-006: The audit log is read-only — no event can be modified or deleted via the UI or API
- **Given**: An authenticated Admin is viewing any event on SCR-017
- **When**: The Admin attempts to edit, delete, or modify any entry (direct or via API call)
- **Then**: No edit, delete, or modify control is exposed in the UI; the API endpoint for audit log returns only GET methods; any non-GET HTTP method on audit log endpoints returns HTTP 405 Method Not Allowed (FR-041, FR-042)

### AC-007: The audit log viewer is accessible only to Admin-role users
- **Given**: A Patient or Staff user attempts to navigate to the audit log screen or calls the audit log API endpoint directly
- **When**: The request is processed
- **Then**: The frontend redirects the user to their role-appropriate dashboard; the API returns HTTP 403 Forbidden; no audit data is disclosed (FR-004, UC-026)

### AC-008: Viewing the audit log screen is itself logged
- **Given**: An authenticated Admin navigates to SCR-017
- **When**: The page renders and the audit API is called
- **Then**: A `PROFILE_VIEWED` (or equivalent `AUDIT_LOG_VIEWED`) entry is written to the audit log with actorId = Admin, resource = "audit_log", timestamp; this prevents silent Admin surveillance of the log (FR-041, HIPAA §164.312(b))

## Edge Cases
* Admin applies date range with no matching events → empty state "No events match the selected filters" shown; no error
* Admin exports a filtered result of 0 events → empty CSV file with headers is produced; export event still logged
* Pagination: Admin navigates to a page beyond the last page (e.g., direct URL manipulation) → last page shown; no error thrown
* Admin session expires while viewing the log → on the next filter/paginate action, the user is redirected to `/login?redirect=/admin/audit-log`; current filter state is not persisted in server session
* Large result set export (>10,000 rows) → server streams the CSV file; no timeout; client receives file as download (streaming implementation detail for backend task)
