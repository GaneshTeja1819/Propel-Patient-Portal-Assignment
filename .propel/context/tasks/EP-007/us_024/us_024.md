# User Story - US_024

## Story ID
* ID Format: US_024

## Story Title
* Admin User and Role Management Dashboard

## Description
* As an authenticated Admin, I want to create, update, deactivate, and change the role of any user account within a cohesive dashboard workflow, so that I can manage platform access without developer involvement and every change is traceable to my Admin identity.

## Acceptance Criteria

### AC-001: Admin can create, update, deactivate, and change roles within 2 screen transitions
- **Given**: An authenticated Admin is on the user management dashboard (SCR-015)
- **When**: The Admin searches for a user, selects their account, and performs a create/update/deactivate/role-change action
- **Then**: The action is completed in ≤ 2 screen transitions from the dashboard (search → select → action on the same page); no separate page per action is required (UC-017, UXR-105)

### AC-002: Role change invalidates the affected user's active sessions
- **Given**: An Admin changes a user's role from Staff to Patient
- **When**: The role change is saved
- **Then**: All active Redis session tokens for that user are invalidated; the user's next request returns HTTP 401 and they are redirected to login; the audit log records the role change with Admin actor, old role, new role, and timestamp (UC-017)

### AC-003: Admin cannot deactivate their own account
- **Given**: An Admin is viewing their own account in the user management dashboard
- **When**: The Admin attempts to deactivate their own account
- **Then**: The deactivation action is blocked with a message "You cannot deactivate your own account"; the account status does not change; no audit log entry is written for the blocked action (UC-017 Extension 3a)

### AC-004: Downgrade from Admin role requires explicit confirmation
- **Given**: An Admin attempts to change another Admin's role to a lower role (Staff or Patient)
- **When**: The role change is initiated
- **Then**: A confirmation dialog appears showing "This will revoke Admin access for [username] — confirm?"; the role change proceeds only after explicit confirmation; cancelled action leaves the role unchanged (UC-017 Extension 3b)

### AC-005: All admin actions are written to immutable audit log
- **Given**: An Admin performs any action (create, update, deactivate, role change)
- **When**: The action completes
- **Then**: An immutable audit log entry is created with actorId (Admin), actorRole = "Admin", actionType, targetEntity = "User", targetId, and timestamp; the entry cannot be updated or deleted

## Edge Cases
* Admin searches for a user by email with no matches → an empty state message is shown ("No users found matching your search"); no error is thrown; the Admin can refine the search
* Admin session expires mid-action (15-minute timeout) → the action is not saved; the Admin is redirected to login; on re-authentication they are returned to the user management dashboard (no data is lost for actions not yet saved)
* Deactivating a user who is currently in an active session → the session is invalidated at the Redis layer; the deactivated user's in-flight requests return HTTP 401
