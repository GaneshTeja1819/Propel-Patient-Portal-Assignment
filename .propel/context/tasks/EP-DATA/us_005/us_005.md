# User Story - US_005

## Story ID
* ID Format: US_005

## Story Title
* Provision PostgreSQL Schema and Domain Entity Migrations

## Description
* As a developer, I want all domain entity EF Core migrations applied to the Supabase PostgreSQL database with the pgvector extension provisioned and referential integrity enforced, so that every feature team can persist data to a consistent, HIPAA-ready schema from the first sprint.

## Acceptance Criteria

### AC-001: All domain entity migrations apply cleanly
- **Given**: The EF Core migration scripts for all 15+ domain entities exist in the Infrastructure project
- **When**: `dotnet ef database update` is executed against the Supabase connection string
- **Then**: All tables are created with correct columns, data types, and constraints; the command exits with code 0 and reports zero failures

### AC-002: pgvector extension is provisioned
- **Given**: The Supabase PostgreSQL instance is running
- **When**: The migration that creates the `vector` extension is applied
- **Then**: `SELECT * FROM pg_extension WHERE extname = 'vector'` returns one row; vector columns can be created and queried (DR-004)

### AC-003: Referential integrity constraints are present
- **Given**: Domain entity tables are created with foreign key definitions
- **When**: An attempt is made to insert a row that violates a foreign key constraint (e.g., Appointment with a non-existent patientId)
- **Then**: PostgreSQL returns a constraint violation error; the insert is rejected; the application logs the error and returns an appropriate error response (DR-002)

### AC-004: InsuranceRecord dummy seed data is loaded
- **Given**: The database seeder runs after migrations
- **When**: `SELECT COUNT(*) FROM insurance_records` is executed
- **Then**: The result is ≥ 1 row; each row has a non-null providerName and insuranceIdPattern

### AC-005: Supabase PITR backup is confirmed
- **Given**: The Supabase project has PITR enabled in its settings
- **When**: The project configuration is reviewed post-deployment
- **Then**: PITR is active with a recovery window of ≥ 1 day; the confirmation is documented in the deployment checklist (DR-007)

## Edge Cases
* Migration applied to a non-empty database (re-run scenario) → `dotnet ef database update` is idempotent; already-applied migrations are skipped; no data loss occurs
* Supabase free-tier storage limit reached → migration succeeds; a post-migration check script reports remaining storage and alerts when usage exceeds 80% of the free-tier limit
* pgvector extension not available on current Supabase plan → migration step that creates the extension fails with a descriptive error; pipeline exits non-zero; team is notified to verify Supabase plan
