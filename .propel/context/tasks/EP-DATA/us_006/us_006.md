# User Story - US_006

## Story ID
* ID Format: US_006

## Story Title
* Implement PHI Encryption and Append-Only Audit Schema

## Description
* As a security engineer, I want AES-256-GCM PHI field encryption integrated into the data layer and an append-only audit log schema with INSERT-only database privileges, so that all patient health information is encrypted at rest and every user action is immutably recorded in compliance with HIPAA.

## Acceptance Criteria

### AC-001: PHI fields are encrypted before persistence
- **Given**: An entity containing a PHI field (e.g., IntakeRecord.fields, ExtractedClinicalData.vitals) is saved via EF Core
- **When**: The data is read directly from PostgreSQL using a database client (bypassing the application)
- **Then**: The stored column value is ciphertext (not readable plaintext); the application layer decrypts it correctly on read (DR-001, NFR-004, FR-040, TR-015)

### AC-002: Encryption keys are loaded from environment variables only
- **Given**: The AES-256-GCM key configuration is set up
- **When**: The source repository is scanned for raw key values
- **Then**: Zero key values are found in any committed file; the key is loaded exclusively from `Environment.GetEnvironmentVariable` or GitHub Secrets injection (DR-001)

### AC-003: Audit schema is INSERT-only for the application role
- **Given**: The `audit.audit_log` table exists in the dedicated `audit` schema
- **When**: The application database role attempts `UPDATE` or `DELETE` on an audit log row
- **Then**: PostgreSQL returns a permission denied error; only `INSERT` and `SELECT` succeed for the application role (DR-003, TR-014, NFR-007, FR-041)

### AC-004: Audit log entry is written for every tracked action
- **Given**: An auditable action occurs (e.g., patient registration, appointment booking)
- **When**: The action completes successfully
- **Then**: A new row appears in `audit.audit_log` with non-null actorId, actorRole, actionType, targetEntity, targetId, and timestamp; the row count increases by exactly 1

### AC-005: Encrypted blob storage path (not content) in relational DB
- **Given**: A clinical PDF document is uploaded and stored in Supabase Storage
- **When**: The ClinicalDocument row is read from PostgreSQL
- **Then**: The `storagePath` column contains an encrypted path string; the actual file binary is not present in the relational table (DR-005)

### AC-006: HIPAA data retention deletion scaffolding is functional
- **Given**: A patient-requested deletion endpoint exists at `DELETE /api/v1/patients/{id}/data`
- **When**: An Admin calls the endpoint for a patient
- **Then**: PHI data is marked for deletion per retention policy; an audit log entry records the deletion request with actorId, timestamp, and targetId; the endpoint returns HTTP 202 (DR-006)

## Edge Cases
* Encryption key rotation → existing ciphertext cannot be decrypted with the new key; migration tooling re-encrypts all PHI fields with the new key before the old key is decommissioned; zero downtime required
* Application role accidentally granted UPDATE on audit schema → integration test asserts `UPDATE` returns `42501 insufficient_privilege`; CI gate fails if permission check does not pass
* PHI field value exceeds maximum ciphertext length for the column → EF Core model validation raises a `DbUpdateException`; the application returns HTTP 422 with a field-level validation error
