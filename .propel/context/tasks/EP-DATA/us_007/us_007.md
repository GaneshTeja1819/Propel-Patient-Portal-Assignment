# User Story - US_007

## Story ID
* ID Format: US_007

## Story Title
* Configure JWT Authentication with HttpOnly Cookies

## Description
* As a security engineer, I want JWT access tokens issued with a 15-minute expiry stored in HttpOnly Secure SameSite=Strict cookies and refresh tokens stored server-side in Redis, so that session management is XSS-resistant and inactive sessions are automatically terminated at the 15-minute threshold.

## Acceptance Criteria

### AC-001: JWT is issued in an HttpOnly Secure cookie
- **Given**: A user submits valid credentials to `POST /api/v1/auth/login`
- **When**: The response is returned
- **Then**: The response includes a `Set-Cookie` header with `HttpOnly`, `Secure`, and `SameSite=Strict` attributes; the JWT is not present in the response body; the cookie contains a valid JWT signed with the configured key (TR-007)

### AC-002: JWT expires after exactly 15 minutes
- **Given**: A JWT is issued at time T
- **When**: A request is made at time T + 15 minutes + 1 second using that JWT
- **Then**: The API returns HTTP 401; the response body does not expose expiry details; the session is considered invalid

### AC-003: Refresh token is stored server-side in Redis only
- **Given**: A JWT is issued successfully
- **When**: The Redis store is inspected for the session key
- **Then**: A refresh token entry exists in Redis keyed by session ID; the refresh token is never present in the response body or any client-accessible cookie

### AC-004: Inactive session auto-terminates at 15 minutes
- **Given**: An authenticated user has a valid JWT cookie
- **When**: The user makes no requests for 15 minutes
- **Then**: The Redis session key expires; any subsequent request with the expired JWT returns HTTP 401; the client is redirected to the login page (NFR-006)

### AC-005: CORS is restricted to InfinityFree origin only
- **Given**: The .NET API CORS policy is configured
- **When**: A preflight request originates from a domain other than the InfinityFree production URL
- **Then**: The API returns HTTP 403; no CORS headers are present in the response; wildcard origins are never accepted (NFR-005 constraint — OWASP A05)

## Edge Cases
* User presents a JWT from a previous session after password change → the old JWT is rejected at the signature validation step; the user must re-authenticate
* Redis unavailable when refresh is attempted → the API returns HTTP 503 with a `Retry-After` header; the JWT cannot be refreshed; the user must re-authenticate once Redis recovers
* JWT forged or tampered → signature validation fails; HTTP 401 is returned immediately; no sensitive information is disclosed in the error response
