# User Story - US_003

## Story ID
* ID Format: US_003

## Story Title
* Configure Hangfire and Upstash Redis Services

## Description
* As a developer, I want Hangfire configured with PostgreSQL persistence and Upstash Redis configured as the caching client, so that background job scheduling and real-time slot cache invalidation are ready for all feature teams to use without additional infrastructure setup.

## Acceptance Criteria

### AC-001: Hangfire registers and the dashboard is accessible
- **Given**: Hangfire is configured with the PostgreSQL job store in the Infrastructure project
- **When**: The .NET API starts
- **Then**: Hangfire schema tables are created in the PostgreSQL database; the Hangfire dashboard is accessible at `/hangfire` with Basic Auth protection; no job-registration errors appear in startup logs

### AC-002: Upstash Redis client connects and responds
- **Given**: The Upstash Redis connection string is injected from environment variables
- **When**: The API performs a test `PING` command during startup health check
- **Then**: The Redis client returns `PONG`; the connection is established within 2 seconds; a failed connection does not crash the API but logs a warning

### AC-003: Hangfire job retry configuration matches NFR-008
- **Given**: Hangfire's global job filter is configured with 3 retry attempts and exponential back-off
- **When**: A test job is registered that throws an exception on first invocation
- **Then**: Hangfire retries the job 3 times with increasing delay (10 s, 60 s, 360 s); after the third failure the job transitions to the Failed state; no additional retries occur

### AC-004: Redis slot cache TTL is set to 5 seconds
- **Given**: A slot availability key is written to Redis
- **When**: 5 seconds elapse without cache renewal
- **Then**: The key expires and returns null on the next read (TTL ≤ 5 s per TR-005/NFR-002)

### AC-005: Credentials are never in source code
- **Given**: Upstash Redis connection string and Hangfire Basic Auth credentials are defined
- **When**: The source repository is scanned for plaintext connection strings
- **Then**: No credential values are found in any committed file; values are loaded exclusively from environment variables or GitHub Secrets

## Edge Cases
* Upstash Redis free-tier connection limit reached → connection pool returns a timeout; the application logs the error and falls through to a database read; slot data served from DB with a staleness warning in logs
* PostgreSQL Hangfire schema migration fails on startup → API logs the migration error and exits with a non-zero code; CI deployment gate treats this as a failed deployment
* Hangfire dashboard exposed without authentication → integration test asserts HTTP 401 when accessing `/hangfire` without credentials
